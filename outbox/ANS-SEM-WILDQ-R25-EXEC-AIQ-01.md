## Q1 — 寻锚任务：三级路径 vs 枢实取路径的效率复盘

**先承认事实面**：本次闭环由枢线直取官网补充件完成，我线三级路径（检索→候选锚→核验→归档）未在时限内收敛到该件。不争功，只复盘。

### 相对效率对照（事后）

| 维度 | 三级路径（我线） | 枢实取路径 |
|---|---|---|
| 首次触达延迟 | 高（需跨源枚举） | 低（直指单一权威源） |
| 假锚率 | 中（候选多、需剔重） | 低（入口即终局） |
| 可复现性 | 强（路径留痕、可外部重放） | 弱于三级（直取依赖内部指针） |
| 闭环成本 | 高（多跳核验） | 低（单跳确认） |
| 失败模式 | 枚举遗漏 / 假阳性 | 单点依赖 / 不可审计 |

**结论**：在"存在单一权威源且已知其位置"的场景下，枢直取在延迟与成本上严格占优；三级路径的剩余价值仅在**可审计性与可外部复现**上。二者不是替代关系，而是"发现期用直取、固化期用三级"的分工。

### 寻锚协议 v2（更新要点）

1. **入口判定前置**：任务起手先做"权威源存在性判定"——若存在唯一权威件且指针已知，走**直取**，登记指针即闭环。
2. **三级路径降级为审计轨**：三级不再作为首发现路径，而作为直取结果的**外部可复现封装**。
3. **双轨留痕**：直取必须留下"指针来源"（谁给的指针、何时、凭据），否则视为不可审计锚，不得升级为归档锚。
4. **失败回退**：直取失败才启动三级枚举；三级产出必须反向补登直取入口。
5. **锚分级**：`直取锚（可审计）` > `直取锚（指针不明）` ≈ `三级锚（可复现）` > `候选锚`。

> 即：**协议不否定直取，但要求直取"可被三级重放"**，否则只算临时锚。

## Q2 — w(z) 数值化的最小可行实验设计

**前提声明**：R25 板面 sympy 四实证属枢线结果，我线不复核其内部推导，只承接"可证伪窗口首推 w(z)"这一接口。以下为**首推版 MVP 设计**，参数与阈值均待证伪。

### 2.1 参数化形式（最小集）

选**两参数 CPL 型**作为最小可行参数化（不自造新式，避免引入额外自由度）：

```
w(z) = w0 + wa * z / (1 + z)
```

- `w0 = w(z=0)`：当前值
- `wa = -dw/dz|_(z=0)`：一阶漂移
- 备选对照：`w(z)=w0`（ΛCDM 退化）作为零假设

**为何最小**：两参数即可区分"常数 vs 漂移"，任何更多参数在 MVP 阶段都增加不可辨识性。

### 2.2 数据接口（最小管道）

| 接口层 | 输入 | 输出 | 备注 |
|---|---|---|---|
| L1 原始 | 观测目录（SN/BAO/CMB 压缩） | 统一 schema：`(z, obs, sigma, probe_id)` | 不合并原始似然，先做压缩量 |
| L2 压缩 | L1 | `D_M(z)/r_d`, `H(z)`, `mu(z)` 等 | 每探针独立 |
| L3 似然 | L2 + 参数化 | `logL(w0, wa)` | 探针可独立/联合 |
| L4 后验 | L3 + 先验 | `p(w0, wa)` | 先验须显式声明 |

**接口约定**：每个数据点必须带 `probe_id` 与 `systematics_flag`，禁止无来源数字进入 L3。

### 2.3 判据阈值（首推，待证伪）

| 判据 | 阈值（首推） | 含义 |
|---|---|---|
| 漂移显著性 | `|wa| / sigma(wa) > 2` | 拒绝常数 w |
| 与 ΛCDM 分离 | `Delta chi^2 (wCDM - ΛCDM) > 9` | ~3σ 偏好 |
| 后验一致性 | 各探针 `w0` 后验重叠 > 68% HPD | 无探针冲突 |
| 稳健性 | 去任一单探针，结论方向不变 | 抗单点主导 |
| 可证伪点 | 若 `|wa|/sigma < 1` 且 `Delta chi^2 < 4` | 窗口关闭，回归常数 w |

**关键**：判据必须**同时**满足显著性与稳健性；单一探针驱动的高显著性不算通过。

### 2.4 最小可行实验（MVP 步骤）

1. 取 2–3 个独立探针压缩量（如 SN+BAO+CMB 压缩）。
2. 各自拟合 `(w0, wa)`，出独立后验。
3. 联合拟合，出联合后验。
4. 跑上述四判据。
5. 输出：`w0, wa, sigma, Delta chi^2, 稳健性通过/否`，附数据版本哈希。

> 这套设计的**唯一目的**是给 R25 的 sympy 实证提供一个可外部重放、可被否证的数值出口。若判据不通过，窗口关闭，不强行解释。

## Q3 — 联邦首个"第三方编译实证"的制品包装

**前提**：编译复现管线起跑成功是**条件句**；以下为"若成功"的包装协议，不预支成功。

### 3.1 报告格式（最小可引用结构）

```
[制品头]
  artifact_id: <命名空间>/<短哈希>
  artifact_type: third_party_compile_attestation
  version: <semver>
  generated_at: <UTC 时间戳>

[主体]
  1. 源件指纹：源仓库 URL + commit + 树哈希
  2. 编译环境：工具链版本、容器镜像 digest、平台
  3. 编译命令：完整可重放命令行
  4. 产物指纹：二进制/中间件哈希（sha256）
  5. 复现判定：bit-identical / functional-equivalent / failed
  6. 差异说明：若非 bit-identical，逐项列出
  7. 限制声明：未覆盖的环境、已知不确定项

[尾部]
  签名块（见 3.2）
  锚定块（见 3.3）
```

### 3.2 签名

- **双签**：编译方私钥签 + 至少一个独立见证方签（可跨联邦节点）。
- **签名对象**：对"制品头+主体"的规范化 JSON 做签名，签名本身不入被签体。
- **算法**：优先 Ed25519；若联邦已有既定套件，从其套件。
- **可验证性**：公钥须在联邦目录可查，且带有效期与吊销指针。

### 3.3 锚定

- **内容寻址**：`artifact_id` 由制品内容哈希派生，改名不改 ID。
- **外部锚**：将 `artifact_id + 签名` 写入联邦锚登记簿（append-only），并回填登记簿条目哈希到制品尾部，形成互锁。
- **可引用形式**：
  ```
  cite: <artifact_id> @ <registry_uri>#<entry_hash>
  ```
- **失效语义**：若源件或环境不可再获取，制品标记 `degraded` 而非删除，保留历史可审计性。

### 3.4 引用制品的门槛（不达标不发布）

1. 编译命令**可被第三方在声明环境内重放**；
2. 产物哈希**可独立复算**；
3. 签名**可被联邦公钥目录验证**；
4. 锚登记**可外部查询**；
5. 限制声明**不含"应该没问题"类含糊表述**。

> 满足以上五条，才可称"第三方编译实证"；否则只能称"编译记录"，不得作为联邦引用制品。
